# 기존 기능 보존·재인수인계 실행 계획

**Goal:** 이전 승인 콘텐츠를 현재 실제 앱에 연결하고, 기능 누락과 숨김·미검증을 구분한다.
**Architecture:** 기존 통합 Auth·원천 회차·동의·결제·실제 회차 저장을 유지한다. 원본 FIVE의 최신 장면 안내만 선별 연결하며 이전 DB 전체를 덮어쓰지 않는다.
**Tech Stack:** 기존 Next.js·React·TypeScript·Supabase·node:test.

## 번호별 완료 기준

1. **인수인계:** `Quantum 출시 후보 현황 점검`에 최신 근거 요청, 원본 인수인계와 FIVE 결정 장부 §12를 대조한다. 새 답변 미회수와 기존 문서 확인을 혼동하지 않는다.
2. **모임:** 현재 성별 무관 모임을 보존한다. 세 비교 작업공간에 성별 전용 계약이 없으므로 삭제 복구라고 주장하지 않는다. 실제 참가 제한인지 분류인지 사용자 답변을 받아 해당 계약만 확장한다.
3. **5일 콘텐츠:** 현재 회차 API를 유지하면서 승인된 장면별 안내와 다음 행동을 복구한다. 보드게임 원천은 Day 2, 다른 원천은 Day 1; 실제 5/6회 번호를 보존한다. 안내 넘기기는 출석·동의·결제·회차 완료를 만들지 않는다.
4. **기능 보존:** 오늘/이번 주, MBTI, 모임, 방문/배달 월드컵, 친구/채팅, 가입과 역할 화면의 경로를 대조한다. 원본 파일 존재 확인과 실제 기능 완주를 따로 기록한다.
5. **검증:** 변경 전 실패 테스트→변경 후 회귀, 직접 모바일/데스크톱 클릭과 캡처, 독립 요구 충족·코드 검토. 남은 실제 DB/복수 계정/결제/기기 범위를 명시한다.

## 확인된 기준 드리프트

- 출시 후보의 app/components/lib 521개 파일은 현재 대상에도 모두 존재한다. 내용·동작 동일성을 증명하지 않는다.
- 커뮤니티 활동 모임 계약은 `COMMUNITY_INTERFACE_CONTRACT.md`와 생성 UI 모두 ‘성별 조건 없음’이다. 매칭 그룹의 mixed 성별 표시는 다른 도메인이다.
- FIVE의 결정 장부 §12(2026-08-27)는 root의 동명 장부에 없는 최신 콘텐츠를 갖는다. root 파일 하나만 읽는 인수인계는 불충분하다.
- 통합 회차에는 Day1~5 저장 골격이 있지만 원본 장면별 안내·시각 연출과 일부 상호작용은 축약됐다. 기존 전체 구현 보고의 ‘Day1~5 구현’을 원본 전체 보존으로 확대 해석하지 않는다.

## 검증 명령과 증거

각 구현은 관련 node:test의 의도된 RED를 기록한 뒤 GREEN을 확인한다. `npx tsc -p tsconfig.matching-tests.json`, `node --test .tmp/matching-tests/tests/matching/*.test.js`, config/auth/profile 회귀와 `npm run typecheck`를 실행한다. UI는 localhost:3010에서 390×844 및 1440×900으로 검사한다. 실데이터 조회가 필요한 화면은 인증/권한을 우회하지 않는다. 실제 변경 파일·결과·캡처·미검증은 최종 보존 보고서에 누적한다.
