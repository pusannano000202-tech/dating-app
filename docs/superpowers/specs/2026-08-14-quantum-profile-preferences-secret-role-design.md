# Quantum 평소 취향·오늘 카드·비밀 역할 설계

- 기준일: 2026-08-14
- 브랜드 기준: Quantum Peach Air

이 문서는 아래 기존 문서의 후속 설계다.

기존 문서와 충돌할 경우 이 문서를 우선한다. 특히 기존 B형 카드의 `오늘의 역할` 공개 규칙은 폐기한다. 역할은 상대 카드에 포함하지 않고 본인만 볼 수 있는 만남별 비밀 미션으로 분리한다.

## 2. 제품 목표

사용자가 매번 같은 취향을 다시 입력하지 않으면서도, 만남마다 새로운 기대와 역할을 가질 수 있게 한다.

전체 경험은 세 층으로 나눈다.

1. `평소의 나`: 마이 화면에서 한 번 저장하고 반복 사용하는 취향
2. `오늘의 나`: 이번 만남에서만 달라지는 짧은 상태와 기대
3. `오늘의 비밀 역할`: 본인만 확인하고 만남 종료 후 서로 맞히는 미션

취소 완료 후 활성 약속이 없다면 취소 카드를 계속 보여주지 않고 전체 매칭 선택 화면으로 즉시 복귀시킨다.

## 3. 범위

### 포함

- 참여 취소 후 매칭 선택 화면 복귀
- 마이 화면의 재사용 가능한 평소 취향 카드
- 만남별 오늘 카드
- 활동별 비밀 역할 자동 배정
- 만남 종료 후 역할 맞히기
- 논쟁 질문 은행과 공개 규칙
- 활동 맥락 색상을 적용한 카드 디자인
- 서버·DB 공개 범위 분리
- 2계정·5계정·반응형·보안 검증

### 제외

- 취향 답변을 이용한 자동 탈락 또는 외모 등급 계산
- 역할 수행 결과를 벌점·보증금·사용자 평점에 반영
- 참가자의 사진·실명·학과·연락처를 만남 전 공개
- 논쟁 질문에 정답이나 우열 부여
- 운영자가 수동으로 모든 역할을 배정하는 관리 화면

## 4. 승인된 사용자 동선

### 4.1 참여 취소

1. 사용자가 `이 약속 참여 취소`를 누른다.
2. 버튼은 즉시 처리 중 상태로 바뀌고 중복 요청을 막는다.
3. 서버가 참여·예약 좌석·대기 초대·비밀 역할을 원자적으로 정리한다.
4. 성공하면 `참여를 취소했어요` 알림을 짧게 보여준다.
5. 다른 활성 약속이 없으면 `/match?choose=another`로 이동한다.
6. 다른 활성 약속이 있으면 그 약속 현황을 보여준다.
7. 실패하면 현재 화면을 유지하고 재시도 가능한 오류를 표시한다.

취소한 약속의 수명주기 기록은 운영 증거로 보존할 수 있지만, 활성 약속 조회와 첫 화면에는 포함하지 않는다.

### 4.2 최초 준비

1. 사용자는 마이 화면의 `내 취향 카드`에서 평소 취향을 저장한다.
2. MBTI와 연애 경계 질문은 선택 항목이다.
3. 필수 항목이 부족하면 참여 직전에 필요한 항목만 채우게 한다.
4. 한 번 저장한 값은 다음 만남부터 자동 재사용한다.

### 4.3 만남 신청

1. 사용자가 활동과 참여 방식을 선택한다.
2. 참여 전 여섯 장 안내를 확인한다.
3. 평소 취향이 준비되어 있으면 반복 질문을 건너뛴다.
4. 사용자는 오늘의 기분·대화 에너지·기대 장면을 30초 안에 선택한다.
5. 서버가 방을 배정하고 평소 취향과 오늘 카드의 안전한 스냅샷을 만든다.
6. 서버가 활동과 방 인원을 기준으로 비밀 역할을 자동 배정한다.
7. 사용자는 자신의 역할만 확인하고 참여를 확정한다.

### 4.4 방 화면

- 다른 참가자의 얼굴 대신 익명 좌석과 성별을 표시한다.
- 좌석을 누르면 평소 취향과 오늘 카드만 열린다.
- 비밀 역할, 내부 사용자 ID, 사진, 외모 점수는 응답에도 포함하지 않는다.
- 카드 답변이 없으면 가짜 값을 만들지 않고 준비 중 상태를 표시한다.

### 4.5 만남 종료 후

1. 만남 종료 상태가 확인된 뒤 역할 맞히기 화면이 열린다.
2. 참가자는 다른 사람의 역할을 추측한다.
3. 모든 제출이 끝나거나 운영 종료 시간이 지나면 역할을 공개한다.
4. 결과는 가벼운 회고로만 사용하고 평점·보증금·매칭 점수에 반영하지 않는다.

## 5. 정보 분리

### 5.1 평소 취향

마이 화면에서 관리하고 다음 만남에 재사용한다.

- MBTI: 선택
- 대화 에너지: 잘 들어요 / 균형형 / 먼저 말해요
- 약속 스타일: 계획형 / 균형형 / 즉흥형
- 관심사 3~5개
- 자주 듣는 음악
- 음식·생활 취향 답변
- 연애 경계 질문 답변: 선택
- 수정 시각과 질문 은행 버전

수정한 내용은 앞으로 생성되는 스냅샷에만 반영한다. 이미 편성된 방의 카드는 중간에 바꾸지 않는다.

### 5.2 오늘 카드

만남마다 새로 저장한다.

- 오늘의 기분 또는 에너지
- 이번 활동에서 기대하는 장면
- 활동별 짧은 선택 한 가지

자유 입력은 최소화하고 연락처·SNS·링크·실명 유도 문구를 서버에서 차단한다.

### 5.3 비밀 역할

역할은 공개 카드와 별도 저장한다.

- 이벤트 회차와 참가자에 귀속
- 본인 전용 조회
- 시작 전 한 번만 변경 가능
- 취소·방 이동·회차 변경 시 기존 역할 무효화
- 만남 종료 전 다른 참가자에게 공개 금지

## 6. 역할 체계

### 6.1 기본 역할 5종

| 역할 | 본인에게 보이는 미션 | 안전 기준 | 기대 효과 |
|---|---|---|---|
| 탐구자 | 취향과 경험을 묻는 열린 질문을 2번 건넨다 | 사생활·연락처·외모 평가 질문 금지 | 대화 시작과 참여 기회 확대 |
| 리액터 | 상대의 말에 진정성 있는 호응을 보낸다 | 조롱·과장·성적 표현 금지 | 말한 사람이 환영받는 분위기 |
| 세심한 관찰자 | 행동·배려·취향을 한 번 구체적으로 칭찬한다 | 신체·외모 비교와 평가 금지 | 자존감과 관찰력 향상 |
| 대화의 다리 | 조용한 참가자를 자연스럽게 대화에 연결한다 | 답변 강요와 특정인 몰아가기 금지 | 대화 편중과 소외 방지 |
| 페이스 메이커 | 활동의 다음 단계나 쉬는 시점을 제안한다 | 통제·명령보다 선택 제안 사용 | 활동 흐름과 몰입 유지 |

### 6.2 배정 규칙

- 5명 방은 역할을 하나씩 중복 없이 배정한다.
- 3~4명 방은 활동에 적합한 핵심 역할을 중복 없이 선택한다.
- 친구끼리 신청해도 역할은 개인 단위로 배정한다.
- 같은 사용자가 연속해서 같은 역할만 받지 않도록 최근 이력을 고려한다.
- 접근성·성격 부담을 위해 시작 전에 한 번 변경할 수 있다.
- 변경 시에도 다른 사람의 역할은 볼 수 없다.

### 6.3 활동별 표현

역할 이름은 유지하되 활동에 맞는 미션 문구를 제공한다.

- 조깅: 페이스 메이커가 속도와 쉬는 지점을 제안
- 보드게임: 탐구자가 선호 장르를 묻고 페이스 메이커가 다음 게임을 제안
- 산책: 대화의 다리가 소외된 사람에게 질문을 연결
- 맛집: 세심한 관찰자가 메뉴 선택이나 배려 행동을 칭찬
- 술자리: 리액터가 과음을 부추기지 않는 호응을 사용

## 7. 논쟁 질문 은행

첨부 자료는 질문 후보 참고용이다. 자료에 포함된 찬반 평가나 다수 의견은 앱의 정답으로 채택하지 않는다.

### 7.1 음식·취향

- 짜장 / 짬뽕
- 부먹 / 찍먹
- 민초 / 반민초
- 물냉 / 비냉

평소 취향 카드에 저장할 수 있다.

### 7.2 연애 경계

- 깻잎을 대신 눌러주기 가능 / 불편
- 친구의 새우 껍질을 까주기 가능 / 불편
- 친구의 패딩 지퍼를 올려주기 가능 / 불편
- 연인의 차에 이성 친구 블루투스 기록 가능 / 불편
- 연인이 내 친구와 남아 술 마시기 가능 / 불편
- 깜짝 이벤트를 위해 내 친구와 연락하기 가능 / 불편

선택 입력으로 두고 모든 참가자에게 일괄 공개하지 않는다. 사용자가 공개를 허용한 답변 중 대화 소재 1개만 카드에 표시할 수 있다.

### 7.3 관계·예의

- 친구가 연인이 먹던 핫도그 한 입 먹기 가능 / 불편

### 7.4 만남 중 랜덤 밸런스 게임

- 여름에 겨울옷 / 겨울에 여름옷
- 평생 라면 / 평생 치킨
- 자는 방에 모기 / 바퀴벌레
- 탄산 없는 콜라 / 녹아 미지근한 아이스크림

이 항목은 성향 프로필이 아니라 현장 대화용 콘텐츠로 사용한다.

### 7.5 질문 계약

- 모든 질문은 `A`, `B`, `모르겠어요/건너뛰기`를 제공한다.
- 선택지 문구는 중립적으로 작성하고 정답·정상·이상 표현을 금지한다.
- 질문 은행과 답변은 버전을 가진다.
- 삭제된 질문은 새 카드에 노출하지 않되 기존 답변 감사 기록은 보존한다.
- 취향 답변은 자동 탈락, 보증금, 신고 판단에 사용하지 않는다.
- 한 카드에는 흥미로운 답변을 최대 3개만 표시한다.

## 8. 카드 디자인

### 8.1 공통 구조

- 바탕: Quantum Peach Air
- 카드 모서리: 최대 8px
- 상단: 익명 참가자 번호, 성별, 오늘 상태
- 본문: 평소 취향 요약, 음악, 관심사, 논쟁 답변 2~3개
- 하단: `오늘 카드`를 별도 색상 띠로 표시
- 비밀 역할: 공개 카드가 아닌 잠금 표시가 있는 본인 전용 봉인 카드

### 8.2 활동별 보조색

- 음악: 보라 + 금색
- 산책·조깅: 녹색
- 보드게임: 청색 + 코랄
- 맛집: 따뜻한 빨강 + 노랑
- 비밀 역할: 짙은 잉크색 + 금색 봉인

보조색은 카드 구분과 아이콘에만 사용하고 전체 화면을 한 색으로 덮지 않는다. 색상만으로 상태를 전달하지 않고 아이콘과 문구를 함께 사용한다.

## 9. 시스템 경계

구현 시 개념적으로 아래 저장 경계를 유지한다. 실제 테이블명은 구현 계획에서 현재 스키마와 충돌 여부를 확인해 확정한다.

### 9.1 평소 취향 저장소

- 소유자만 쓰기
- 본인은 전체 조회
- 방 카드 생성기는 공개 허용 항목만 읽기
- 질문 은행 버전과 수정 시각 보존

### 9.2 만남 카드 스냅샷

- 이벤트 회차·방·참가자 기준 불변 스냅샷
- 같은 방의 활성 참가자만 안전한 공개 항목 조회
- 다른 방·비참가자·취소자는 조회 거절
- 내부 사용자 ID를 클라이언트 응답에 포함하지 않음

### 9.3 비밀 역할 저장소

- 역할 배정은 서버 또는 제한된 DB 함수만 수행
- 사용자는 자기 역할만 조회
- 다른 참가자 역할 조회는 만남 종료 전 거절
- 역할 맞히기 API는 역할 정답을 먼저 반환하지 않음

## 10. 오류 처리

- 취소 실패: 참여 상태를 유지하고 재시도 안내
- 취향 불러오기 실패: 빈 취향으로 덮어쓰지 않고 저장 중단
- 질문 버전 불일치: 유효한 답변만 보존하고 필요한 질문만 다시 요청
- 역할 배정 충돌: 방 잠금 또는 원자적 배정으로 중복 역할 방지
- 역할 조회 권한 없음: 구체적인 역할 존재 여부를 누설하지 않는 일반 오류
- 만남 종료 상태 미확인: 역할 맞히기와 정답 공개 차단
- 방 이동: 이전 스냅샷과 역할을 폐기하고 새 방 기준으로 재생성

## 12. 검증 순서

1. 순수 함수와 스키마 계약 테스트

3. DB 권한과 직접 호출 공격 테스트
4. 2계정 평소 취향·오늘 카드 E2E
5. 5계정 역할 배정·비공개·맞히기 E2E
6. 취소·새로고침·뒤로가기·방 이동 검증
7. 390x844와 1440x900 실제 브라우저 클릭·화면 검증
8. 원격 Supabase 적용 여부와 Vercel·Android 상태를 로컬 결과와 분리 보고

## 13. 구현 단계 경계

1. 기존 취소·카드·방 계약을 테스트로 고정
2. 평소 취향과 만남 카드의 타입·API 경계 구현
3. 취소 성공 후 선택 화면 복귀 구현
4. 비밀 역할 배정·본인 조회·변경 구현
5. 역할 맞히기와 종료 후 공개 구현
6. 카드·마이 화면·역할 UI 구현
7. 보안·E2E·반응형 검증

DB 마이그레이션, 공용 타입, API 경계는 위험 변경으로 분리한다. 현재 작업 폴더의 기존 변경과 섞지 않고 파일별 소유권과 커밋 범위를 먼저 확정한다.

## 14. 완료로 말하지 않는 상태

- 취소 성공 문구만 바뀌고 실제 참여·예약·초대·역할이 남은 상태
- 평소 취향이 화면에만 있고 저장 후 재조회되지 않는 상태
- 역할 카드가 본인 화면에 보이지만 타인 API 접근을 막지 못한 상태
- 5명 역할 배정을 정적 예시로만 보여준 상태
- 로컬 테스트만 통과하고 2계정·5계정 E2E를 하지 않은 상태
- 로컬 마이그레이션 파일만 있고 원격 적용 여부를 확인하지 않은 상태
- 로컬 화면을 Vercel 또는 Android 운영 검증으로 표현한 상태
