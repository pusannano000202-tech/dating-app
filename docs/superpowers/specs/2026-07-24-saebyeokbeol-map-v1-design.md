# 새벽벌도서관 1차 3D 맵 설계

- 상태: 사용자 설계 승인 완료
- 승인일: 2026-07-24
- 대상 프로젝트: `prototypes/saebyeokbeol-map-v1/`
- 실행 환경: 휴대폰·데스크톱 웹브라우저 WebGL

## 1. 목표

부산대학교 새벽벌도서관 공식 층별 안내도와 2026년 최신 사진을 바탕으로, 캐릭터가 1층과 2층의 핵심 공개 구역을 끊김 없이 왕복할 수 있는 독립형 3D 맵을 만든다.

이번 버전은 공간 구조, 3인칭 조작, 걷기·달리기, 계단 이동, 모바일 브라우저 성능을 검증하는 첫 번째 플레이 가능한 수직 단면이다. 기존 과팅앱과 패키지·실행 명령·소스 경계를 분리한다.

## 2. 승인된 제품 결정

| 항목 | 결정 |
|---|---|
| 맵 범위 | 1층과 2층 연결형 |
| 완료 수준 | 캐릭터 자유 이동형 |
| 카메라 | 3인칭 뒤따라가기 |
| 실행 방식 | 휴대폰 브라우저 WebGL |
| 프로젝트 위치 | 기존 과팅앱과 분리된 독립 미니 프로젝트 |
| 이동 기능 | 걷기와 달리기 |
| 그래픽 우선순위 | 캐릭터보다 공간 재질·조명·구조 우선 |
| 성능 기준 | 일반적인 휴대폰 브라우저에서 안정적인 30fps 목표 |

## 3. 범위

### 3.1 플레이 가능한 1층

- 주출입구와 안내 구역
- 새벽누리
- 새벽마루
- 위 공간을 연결하는 공개 복도
- 2층으로 이어지는 중앙 계단

오디토리움, 매체제작실, 매체편집실, 매점, 카페 내부는 외벽과 출입문만 표현하고 들어갈 수 없게 한다.

### 3.2 플레이 가능한 2층

- 중앙 계단 도착부
- 사물함 복도
- 제1열람실

새벽별당, 도서관자치위원회실, 화장실 내부는 외벽과 출입문만 표현하고 들어갈 수 없게 한다.

### 3.3 플레이 경로

1. 1층 주출입구에서 캐릭터가 생성된다.
2. 새벽누리와 새벽마루를 자유롭게 순환한다.
3. 중앙 계단으로 2층에 올라간다.
4. 사물함 복도를 지나 제1열람실을 자유롭게 탐색한다.
5. 같은 경로로 1층 시작점까지 돌아온다.

### 3.4 이번 버전에서 제외

- 온라인 플레이어 동기화
- 로그인과 대학생 인증
- 술래·도망자 역할과 잡기 판정
- NPC와 봇
- 음성채팅
- 캐릭터 꾸미기
- 앱스토어용 네이티브 빌드
- 3층과 4층
- 비공개·직원 전용 공간의 내부

## 4. 조작과 카메라

### 4.1 모바일

- 왼쪽 가상 스틱: 걷기
- 달리기 버튼을 누른 상태에서 이동: 달리기
- 화면 오른쪽 영역 드래그: 카메라 회전
- 점프 기능은 제공하지 않는다.

점프를 제외해 계단·가구·난간을 넘어 맵 밖으로 빠지는 문제를 줄이고, 술래잡기에 필요한 이동 검증에 집중한다.

### 4.2 데스크톱 QA

- `WASD`: 이동
- 마우스 드래그 또는 포인터 잠금: 카메라 회전
- `Shift`: 달리기
- 초기화 단축키: 1층 시작점으로 복귀

### 4.3 캐릭터

- 저폴리 학생 캐릭터 한 명
- 걷기와 달리기 상태
- 캡슐 형태의 충돌체
- 외형 완성도보다 공간에서 크기와 이동 속도가 자연스럽게 느껴지는 것을 우선한다.

### 4.4 3인칭 카메라

- 캐릭터 뒤쪽과 위쪽에서 따라간다.
- 벽이나 천장과 캐릭터 사이에 장애물이 생기면 카메라 거리를 자동으로 줄인다.
- 장애물이 사라지면 원래 거리로 부드럽게 복귀한다.
- 계단을 오르내릴 때 높이 변화가 갑자기 튀지 않도록 완충한다.

## 5. 공간과 시각 설계

### 5.1 구조 기준

- 방, 복도, 계단, 화장실, 엘리베이터의 상대적 위치는 부산대학교도서관 공식 1·2층 안내도를 기준으로 한다.
- 안내도에 실제 치수가 없으므로 1차 맵은 상대 비율 기반이다.
- 문 폭, 복도 폭, 기둥 간격은 사진 속 사람·가구·문을 기준으로 합리적인 게임 축척을 사용한다.
- 향후 실측값을 받으면 맵 좌표 데이터만 수정해 비율을 보정할 수 있어야 한다.

### 5.2 1층 표현

- 밝은 벽돌 기둥
- 목재 천장 또는 목재 계열 마감
- 개방형 라운지
- 원형·사각 테이블과 소파의 혼합
- 넓고 밝은 시야

### 5.3 2층 표현

- 적갈색 벽돌 기둥
- 짙은 목재
- 회색 바닥
- 긴 선형 조명
- 반복되는 열람 책상과 파티션
- 사물함과 측면 복도

### 5.4 모바일 성능 원칙

- 건물과 가구는 단순한 박스형 메시를 조합한다.
- 동일한 책상·의자·조명은 인스턴싱한다.
- 재질 수와 실시간 광원 수를 제한한다.
- 그림자는 주요 캐릭터와 큰 구조물 중심으로 사용한다.
- 기기 성능이 낮으면 렌더링 해상도와 그림자 품질을 자동으로 낮춘다.
- 참조 사진 자체를 벽이나 바닥 텍스처로 붙이지 않는다.

## 6. 기술 구조

### 6.1 프로젝트 격리

새 프로젝트는 `prototypes/saebyeokbeol-map-v1/` 아래에 독립적으로 둔다.

- 독립 `package.json`
- 독립 개발·빌드·테스트 명령
- 기존 Next.js 앱의 `package.json`, API, DB, 인증, 공용 타입을 수정하지 않음
- Supabase와 결제 코드에 의존하지 않음

### 6.2 모듈

| 모듈 | 책임 |
|---|---|
| `map-data` | 층별 벽·문·계단·기둥·가구 좌표 정의 |
| `map-builder` | 좌표 데이터를 Three.js 메시와 충돌체로 변환 |
| `materials` | 벽돌·목재·바닥·금속·조명 재질 제공 |
| `player` | 캐릭터 위치, 걷기·달리기 속도, 충돌 처리 |
| `camera` | 3인칭 추적과 벽 관통 방지 |
| `input` | 모바일 터치와 데스크톱 입력을 공통 이동 명령으로 변환 |
| `performance` | 화면 해상도, 그림자, 프레임 측정과 품질 하향 |
| `ui` | 가상 스틱, 달리기 버튼, 층 표시, 초기화 안내 |

각 모듈은 하나의 책임만 가지며, 맵 좌표 데이터는 렌더링 구현과 분리한다.

### 6.3 데이터 흐름

1. 층별 맵 좌표 데이터를 읽는다.
2. 맵 빌더가 구조물 메시와 충돌 데이터를 만든다.
3. 입력 모듈이 터치 또는 키보드 입력을 이동 명령으로 변환한다.
4. 플레이어 모듈이 이동·달리기·충돌을 계산한다.
5. 카메라 모듈이 플레이어와 장애물 위치를 기준으로 시점을 갱신한다.
6. 렌더러가 장면을 그리고 성능 모듈이 프레임 상태를 감시한다.

## 7. 오류와 복구

| 상황 | 처리 |
|---|---|
| 재질 또는 텍스처 로딩 실패 | 단색 대체 재질을 사용하고 맵은 계속 실행 |
| 캐릭터가 맵 아래로 추락 | 1층 시작점으로 자동 복귀 |
| 캐릭터가 플레이 경계를 이탈 | 마지막 안전 위치 또는 1층 시작점으로 복귀 |
| 휴대폰 프레임 저하 | 렌더링 해상도와 그림자 품질을 단계적으로 하향 |
| WebGL 미지원 | 지원되지 않는 기기라는 안내와 권장 브라우저 정보 표시 |
| 화면 회전 또는 크기 변경 | 렌더러와 터치 조작 영역을 새 화면 크기에 맞춰 갱신 |

## 8. 검증

### 8.1 자동 검증

- 맵 데이터의 층·구조물 식별자가 중복되지 않는지 검사
- 스폰 위치가 충돌체 내부나 맵 밖에 있지 않은지 검사
- 1층과 2층 계단 연결점이 서로 대응하는지 검사
- 걷기 속도보다 달리기 속도가 큰지 검사
- 프로덕션 빌드 성공
- 정적 분석과 테스트 성공

### 8.2 브라우저 직접 검증

- 모바일 390×844
- 일반 데스크톱
- 1층 입구에서 2층 제1열람실까지 왕복
- 걷기와 달리기 전환
- 계단 오르내리기
- 벽·가구 관통 여부
- 카메라의 벽·천장 관통 여부
- 맵 밖 추락 후 자동 복귀
- 화면 요소 겹침과 터치 입력
- 브라우저 콘솔 오류
- 모바일 기준 프레임 안정성

문제가 발견되면 수정 후 동일 경로를 다시 검증한다.

## 9. 완료 조건

- 휴대폰과 데스크톱 브라우저에서 맵이 열린다.
- 캐릭터가 걷기와 달리기로 1층과 2층 핵심 경로를 왕복한다.
- 계단 이동이 가능하다.
- 캐릭터가 벽과 주요 가구를 통과하지 않는다.
- 카메라가 벽과 천장 안으로 들어가지 않는다.
- 맵 밖으로 추락하면 복귀한다.
- 1층과 2층이 공식 배치도의 상대적 공간 관계를 따른다.
- 1층과 2층의 재질·조명 분위기가 확보한 사진 자료와 명백히 충돌하지 않는다.
- 모바일 390×844에서 조작 UI가 겹치지 않는다.
- 프로덕션 빌드와 자동 테스트가 통과한다.
- 완료 보고에 모바일·데스크톱 캡처, 검증 결과, 남은 오차를 포함한다.
