## 1. 현행 화면 점검

1. 커뮤니티: 개선 필요. 상단 MBTI/맛집/배달 캐러셀이 큰 면적을 차지하고, 보이스는 그 아래 카드 하나, 게시판은 칩과 바로가기에 흩어져 있다. 맛집·게시판 진입이 여러 번 반복된다. 장점은 사진과 기존 색상이 일관적이라는 점이다.
2. 매칭 → 코스 펼침 → Day 5: 요구 불일치 확인. 실제 첫 만남이 없어도 일반 로그인 사용자가 전체 코스 안내와 미래 회차 그림을 볼 수 있다. 여기서 공개 발견 화면은 비로그인 접근 가능이라는 뜻이 아니다. 이는 학습용 코스 소개로 구현된 상태이며, 이번에 명시한 기대감·비공개 방향과 충돌한다.
3. 채팅: 빈 목록만 확인. 현재 계정에서 열린 매칭방이 0개라 실제 대화 내부로 진입하지 못했다. 이 화면만으로 전송·읽음·실시간 품질을 평가하지 않는다.

## 2. 공통 설계 — 사용자 확정 요구

### U1. 콘텐츠 / 게시글 / 보이스

- 홈 진입의 면적·제목 크기·클릭 깊이를 동등하게 한다. 첫 화면에서 세 축이 모두 보인다. 이는 콘텐츠 수·실제 사용량을 강제로 33.3%로 맞춘다는 뜻이 아니다.
- 중복 메뉴를 통합하고, 카테고리는 해당 영역에 들어간 뒤 표시한다. 글 쓰기 버튼은 게시글 영역에만 둔다.
- 콘텐츠 안에 맛집 월드컵, MBTI 연애 통계, 배달 월드컵, 장소 월드컵을 둔다. 장소에는 PC방·헬스장·보드게임방을 분류한다. 새로운 장소 월드컵은 아직 구현되어 있지 않다.
- 장소별 이용 경험을 바탕으로 선택하고, 가본 곳과 아직 안 가본 곳을 구분한다. 대표 장소 사진·업종·학교와의 관계를 후보 데이터에 보관하고 검수한다. 초기 후보 부족은 준비 중으로 표시하며 가짜 순위나 실제처럼 보이는 가상 매장은 만들지 않는다.
- MBTI는 이용자 자기보고 경험 통계다. 연애 궁합을 과학적으로 예측하거나 학교 전체의 대표 통계처럼 표시하지 않는다.
- 보이스는 이전 요청의 종목→팀→최대 5인 방과 주제별 1:1 고민 나눔으로 연결한다. 운영자/이용자가 매 경기 방을 직접 만들도록 되돌리지 않는다. 학과 수다도 해당 보이스 분류에 보존한다.
- 상위 영역 선택으로 해당 내용만 보이는 상세 화면은 가능하다. 홈에서 특정 영역만 자동 재생·확대해서 다른 두 영역을 묻지 않는다.

### U2. 미래 활동은 미리 공개하지 않는다

- 공개 커뮤니티·매칭/첫 만남 전 화면에서 전체 5일 코스, Day 탭, 잠긴 Day 목록, 미래 활동 그림과 설명을 제거한다. 접어두거나 흐리게 처리하는 것만으로 완료하지 않는다.
- 실제 첫 만남의 참가 완료가 확인된 본인에게만 개인적인 희망 질문을 보여준다: “이 사람들과 더 만나고 싶나요?”
- 본인의 희망 제출은 참가 확정이나 결제가 아니다. 다른 사람의 선택, 거절한 사람, 최종 참가 인원은 임의로 공개하지 않는다.
- 이번 디자인은 시리즈 성립 규칙을 바꾸지 않는다. 현재 SQL은 한 명의 종료 선택에도 전체 시리즈가 종료되는 구조이므로, 찬성한 일부만 남아 자동으로 이어진다고 설명하거나 구현하지 않는다.
- 이어 만남에 참여하는 사람에게도 미래 전체가 아니라 현재 결정/활동에 필요한 정보만 제공한다. 활동의 세부 재미는 해당 회차 진행 시 안내한다.
- 비용·취소 조건·일정·집결 장소·소요 시간·안전·필요 준비물처럼 참여 결정에 필요한 정보는 확정·결제 전에 알린다. 콘텐츠 비공개를 이유로 숨기지 않는다.
- 기존 보드게임 첫 만남 이후 진입 분기와 회차 기록은 그대로 유지한다. 공개 안내를 없앤다는 이유로 실제 후속 기능이나 콘텐츠 자료를 삭제하지 않는다.
- 구현 시 공개 페이지뿐 아니라 직접 URL, API 응답, 클라이언트 번들/공개 이미지 경로도 확인한다. 본인의 참가 자격과 회차 공개 조건에 맞는 자료만 전달한다. 운영자 검토 화면은 참가자 공개 화면과 분리한다.

### U3. 채팅은 익숙하고 빠르게

- 채팅 목록에서 친구·모임·매칭 대화를 일관되게 찾는 방향을 제안한다. 각 종류의 기존 접근 권한과 오픈 시각은 유지한다. 목록 통합이 조기 채팅 개방을 뜻하지 않는다.
- 헤더에는 방 제목·참가자 수·뒤로가기·메뉴. 긴 소개문 대신 작은 고정 공지와 대화가 중심이다.
- 들어온 메시지와 내가 보낸 메시지, 답장 대상, 시간, 새 메시지 경계를 구별한다. 입력창은 키보드 위에 고정한다.
- 보내는 중/실패/재전송/전송 완료/읽음은 실제 서버 상태에 맞춘다. 중복 재전송을 방지하고 초안·뒤로가기·재접속 시 맥락을 보존한다.
- 이전 대화를 읽을 때 새 메시지가 와도 강제로 맨 아래로 이동하지 않는다. “새 메시지” 버튼으로 이동을 선택한다.
- 익명 모임에서는 참가 시점 별명을 사용한다. 수락한 친구의 사적 식별용 이름을 공개 모임에 내보내지 않는다. 자동 친구 추가는 만들지 않는다.
- 문자 대화방마다 음성 통화를 무조건 추가하지 않는다. 보이스는 커뮤니티의 별도 참여 맥락이며 마이크 권한·음소거·나가기·신고·차단을 분명히 한다.

## 4. 참고와 구현 전 확인

[카카오 공식 오픈채팅 소개](https://www.kakaocorp.com/page/service/service/openchat)의 관심사 진입·주제별 방·별도 프로필 방식과 [공식 채팅방 알림 안내](https://pc.kakao.com/talk/notices/ko/2752?agent=mac)의 알림 부담 조절을 참고했다. 사용감의 구조를 참고하며 카카오의 브랜드/화면을 그대로 복제하지 않는다. 카카오 계정에 로그인하거나 실제 대화를 확인한 것은 아니다.

시안은 기본 제공 이미지 생성 도구로 제작하며, 사용자 첨부 사진과 이번 현행 캡처를 실제 참고 이미지로 전달했다. 샘플 대화·사진·인원은 실제 서비스 데이터가 아니다.

실제 구현 완료 판정에는 모바일/데스크톱 상호작용, 긴 메시지·한국어 조합 입력, 키보드, 초안·재접속, 전송 오류·중복 방지, 가입/참가 자격, 읽음 정합성, 미래 회차 직접 접근 거절 검증이 필요하다. 장소 후보의 실재성·이미지 사용 권리·정보 갱신 또한 미검증이다.

이번 보고는 전체 디자인을 함께 선택하기 위한 것이다. 기능 일부만 출시한다고 임의로 나누거나, 시안 제작을 전체 구현 완료로 보고하지 않는다.

## 5. 시안 검토 기록

- 첫 생성 검토에서 라운지 시안의 고민 나눔이 잘못 `최대 5명`으로 표기된 것을 발견했다. 계약은 응원 단체방 최대 5명, 고민 나눔 1:1이다. 구조를 바꾸지 않고 해당 문구만 고친다.
- 라운지/사진형 시안의 채팅 헤더 4명과 샘플 별명 수가 맞지 않아, 본인+세 별명으로 맞추는 정정 이미지를 요청했다. 예시 데이터도 내부적으로 맞아야 한다.
- 원인: 이미지 생성 결과의 문구·샘플 데이터 정합성 오류. 디자인 방향이나 사용자 결정 변경이 아니다. 첫 초안은 선택 대상으로 그대로 인용하지 않고 정정본과 함께 구분한다.
