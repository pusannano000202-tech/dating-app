## 발견해서 수정한 주요 문제

- 친구 초대 SQL 두 곳의 실제 PL/pgSQL 문법 오류.
- 동반 친구 일부만 수락했는데 신청 인원에 포함되던 집계와 최종 배정 뒤 동일 학과 재검사 누락.
- 그룹 운영자와 1대1 방 생성자의 관리 권한 혼동, 학교/학과 변경 후 재입장·집계 재검사 누락.
- 브라우저 마이크 권한 정책과 미디어 서버 연결 주소 검증의 불일치.
- 창 종료 뒤 대기 인원이 남는 문제: 명시 나가기·페이지 종료 요청과 서버의 2분 미연결 유예 정리 연결.
- 음성 종료 작업이 다른 방의 누적 대기 작업 뒤로 밀리는 문제: 해당 방/세션 처리, 제한된 병렬 재시도, 실제 미디어 종료 대기 표시.
- 응답 유실 후 재시도할 때 모임/보이스 모집방이 중복 생성될 가능성.
- 일정 변경 알림의 필드명 불일치와 레거시 자동 친구/전화번호 공개 문구.
- 탈퇴/보존 완료 작업에서 기존 알림 쓰기 가드가 복원되지 않는 문제.
- 지연 처리한 야구 보이스방에서 일정 변경 버튼이 사라지는 문제.
- 일반 대기열 신청이 운영자의 전역 음성 정리 작업을 실행하던 문제.
- 탈퇴 계정의 레거시 화면·API 접근과 서로 다른 Cookie/Bearer 계정이 한 요청에 섞이는 문제.
- 탈퇴 상태 조회 API가 화면에 연결되지 않아 재로그인 후 진행 상태를 볼 수 없던 문제.
- 앨범 삭제 worker가 계정 쓰기 차단 트리거에 막히는 문제. 정확한 처리 job과 허용 필드만 예외로 제한했다.
- 현대 PostgREST JSON JWT 형식에서 탈퇴 차단이 건너뛰어지고 서비스 worker 권한 확인이 실패하던 문제.
- 정적 migration 검사기가 PostgreSQL catalog와 동적 SQL 문자열을 잘못 판정하던 문제. 기존 경고 기준 파일을 갱신하지 않고 회귀 테스트로 수정했다.

Data API 요청 전 검사와 Storage/공개 테이블 RLS를 함께 보강했다. 요청 전 검사는 Data API 전용이므로 다른 제품의 RLS를 대체하지 않는다는 [Supabase 공식 기준](https://supabase.com/docs/guides/api/securing-your-api)을 따랐다. 기존 PostgREST hook과 충돌하거나 Storage RLS가 꺼져 있으면 덮어쓰지 않고 migration을 중단하도록 했다.

Naver 지도·Kakao 공유는 연결하면 해당 기능을 사용할 수 있으며 기존 외부 지도 링크·일반 초대 링크 대체 경로와 구분한다. 야구는 확인되지 않은 자동 KBO API를 붙이지 않았고, **운영자가 공식 일정을 확인해 등록·재확인·지연·취소하는 경기 원장**으로 구현했다. 앱이 스포츠 영상이나 중계 음원을 송출하지 않는다.

1. 최종 코드와 migration 검토, 원본 대비 보존 대조 후 반영할 후보 확정. 커밋/푸시는 별도 승인 대상이다.
2. 승인된 별도 로컬 DB 또는 스테이징에 migration 적용, 실계정 네 역할(사용자·업장·운영자·최고관리자)의 허용/거부 행렬 확인. 기존 사용 DB를 reset하지 않는다.
3. Supabase Auth 전화번호 인증/메일·로그인 리다이렉트·Storage·Realtime, LiveKit 키/웹훅, 실제 호출이 필요한 결제·AI·알림을 연결한다.
4. 두 계정 메시지와 3기기 단체 음성, 네트워크 전환·마이크 거부·차단/강퇴·탈퇴 중 통화·동시 정원을 검증한다. 실제 데이터 수집/마이크 허용은 사용자의 테스트 참여와 별개 권한이다.
5. 결제 승인·취소·환불/실패 복구, Push/작업 스케줄러, 운영자 일정 변경·신고 대응·보관 만료를 검증한다. 파괴적 삭제 worker는 기본 비활성이다.
6. 약관/개인정보 공개 집계 안내·연령/전화 인증·보관 의무·신고 대응 운영 준비를 검토하고, 승인 후 배포와 실제 운영 점검을 진행한다.

외부 계정과 위 검증 없이 'API 키만 넣으면 바로 출시' 또는 '완벽하게 오류 없음'이라고 판단할 수는 없다.

## 별도로 남은 위험과 바로 이어갈 작업

- DB 적용용 파일은 `supabase/migrations/20260906181225_community_social_integrated.sql`이다. 8개 검토 SQL을 단일 transaction으로 묶었으며, 원격 적용하지 않았다. 기존 hook 충돌·기존 데이터 제약·실제 Supabase 권한은 스테이징에서 확인해야 한다.
- 기존에 발급된 Storage 서명 URL은 만료 전까지 접근 가능할 수 있다. 실제 URL TTL, 긴급 객체 회수 절차, 삭제 worker 승인·법적 보관 대상 판정을 확인해야 한다.
- 실제 LiveKit에서 토큰 재사용·강퇴 후 재입장·통화 넘기기 중 잔여 음성이 없는지 검증해야 한다. 로컬 모의 테스트만으로 음성 보안을 확정하지 않았다.
- 맛집·배달 정보의 최신성, 음식 사진 사용 권리, 공개 집계와 개인정보 안내의 운영 검토도 남아 있다.
- 최종 브라우저 재검수는 서버 재기동 명령의 실행 환경 정책 차단으로 미완료다. 작업용 `localhost:3012`는 현재 중지 상태이며, 기존 사용자 서버를 종료하거나 바꾸지 않았다. 허용된 실행 환경에서 재기동 후 계정 상태 화면·전체 로그인 동선을 확인해야 한다.
- 최종 후보 commit/push, 별도 검증 DB migration, 실제 공급자 연결·검수, 배포는 각각 승인된 범위에서 진행해야 한다. 파괴적 worker를 단지 검사 통과를 위해 활성화하지 않았다.
