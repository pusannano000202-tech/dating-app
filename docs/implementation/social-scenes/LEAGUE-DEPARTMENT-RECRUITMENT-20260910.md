# 우리 과 팀 찾기 · 팀원 모집 소식

## 승인 기준

사용자 승인: 같은 학과가 이미 만든 A/B팀을 조회하고, 각 팀은 이름을 직접 정하며, 친구 초대를 받지 않은 사람도 지도 빈자리로 참가 신청한다. “오늘 대회 한 명 부족” 같은 모집 소식으로 그 팀에 사람을 모은다. 직전 추천안에 `ㅇㅇㅇ 해봐`로 구현 승인했다.

기존 지도·친구 초대 계약은 유지한다. 이번 승인은 로컬 구현·검증에 한하며 stage/commit/push/원격 migration/실제 발송/배포는 포함하지 않는다.

## 목표와 완료 조건

### G1. 우리 과 팀 찾기

1. 종목 순위 다음에 `우리 과 팀 찾기`를 기본 참가 진입으로 제공한다. 대전 상대 탐색과 팀원 모집 탐색을 구별한다.
2. 같은 학교·학과·정확한 종목을 서버에서 먼저 필터하고 페이지 단위로 조회한다. 학교 전체 최신 50개 안에 들지 않은 우리 과 팀도 찾아갈 수 있어야 한다.
3. 팀 카드에 자유 팀 이름, 확정 인원/정원, 모집 가능한 포지션을 보여준다. 누르면 기존 지도를 연다. 초대 중 자리는 확정 인원에 포함하지 않지만 무조건 빈자리라고 표시하지도 않는다.
4. 친구가 아니어도 해당 과의 회원은 빈자리·자기 티어/실력 선택 후 참가 신청할 수 있다. 주장이 승인하기 전에는 확정하지 않는다. 대기 표시·신청 취소·승인/거절과 만석/제재/마감 오류를 다룬다.
5. 본인 팀 개설과 기존 친구 초대→수신자 수락 흐름을 보존한다. 목록 바깥 팀을 직접 열어도 상세가 다른 팀으로 바뀌지 않는다.

### G2. 자유 팀 이름

1. A팀/B팀 같은 짧은 이름과 자유 이름을 사용할 수 있도록 팀별 이름을 경기 제목과 분리하여 보존한다.
2. 목록·지도·상대 비교·경기 채팅에서 학과명과 팀 이름을 구별한다. 대전 성사 후에도 양 팀의 이름이 남는다.
3. 기존 데이터는 유효한 기존 모집 제목/안전한 학과명 기반 이름으로 호환하며 소급 데이터 삭제를 하지 않는다. 다른 팀의 이름을 수정할 수 없다.

### G3. 우리 과 모집 소식

1. 현재 주장이 자기 팀 지도에서 `우리 과에 팀원 모집하기`를 선택한다. 팀·종목·빈자리는 서버 상태를 사용하고 희망 시각과 한 줄 설명만 작성한다.
2. 같은 학과의 별도 `우리 과 모집 소식` 탭에 표시한다. 학생 모집 소식이며 학교/학과의 공식 공지라고 표현하지 않는다.
3. 소식은 기존 팀을 가리키며 새 팀이나 채팅방을 만들지 않는다. 열면 해당 팀의 지도와 빈자리로 이동한다.
4. 팀당 활성 소식 하나를 작성/갱신/마감한다. 정원 충원, 모집 시간 경과, 모집 불가능 상태는 마감으로 표시하고 잘못된 참가를 허용하지 않는다.
5. 게시·수정·마감은 현재 주장만 가능하다. 학교·학과·팀 주인·빈자리·작성자·마감 상태를 클라이언트 입력으로 신뢰하지 않는다. 중복 요청·stale revision·팀 위임·차단/제재를 검사한다.

## 발견한 문제와 보완

1. 특정 팀 상세가 없거나 조회에 실패하면 다른 팀이 대신 선택될 수 있던 경로를 막았다. 권한 오류/상세 실패에서 다른 팀의 지도·변경 버튼을 활성화하지 않는다.
2. 상대가 대전을 수락하여 팀의 경기 ID가 바뀌면 이전 ID를 계속 조회하던 연결을 새 응답 ID로 바꿨다.
3. 저장 응답이 잘못된 객체여도 HTTP 성공으로 처리할 수 있던 부분을 결과 DTO 검증으로 보완했다. 인증·출처·입력·오류 응답 테스트와 함께 실패→통과를 확인했다.
4. 옛 팀명에 보이지 않는 문자와 공백이 있으면 새 DB 제약을 적용하지 못하던 문제를 독립 검토에서 재현했다. 원래 모집 제목은 보존하고 별도 팀명만 정규화하는 방식으로 수정했다.
5. 모바일 모집 화면의 중복 제목·불필요한 여백을 줄였다. 화면 단계 전환의 스크롤 시작 위치, 신청/내 팀/만석 안내를 상태에 맞게 정리했다.
6. 모집 소식으로 지도를 연 채 희망 시각이 지나면 신청이 계속 가능하던 경계를 보완했다. 만료 시 UI 갱신, 제출 직전 시간 검사와 실제 서버 상태 재조회, 조회 중 다른 팀 이동/실패 시 신청 취소를 실행 회귀로 확인했다. 일반 팀 목록의 신청은 소식 마감과 독립적으로 유지한다. 최신 수정 후 소식 탭→지도→정상 신청도 브라우저에서 다시 확인했다.

## 남은 환경 경계

- 원격 migration 적용, 실계정 참가·승인·공지 게시, 실기기 푸시는 미검증이다. 이 작업은 실제 푸시 기능을 추가하거나 전송하지 않았다.
- PGlite 테스트는 실제 SQL 로컬 실행이며 다중 DB 세션 부하 시험이 아니다. 마지막 자리의 처리 순서를 양쪽 순서로 검사한 결과를 실제 동시 접속 부하 검증으로 확대하지 않는다.
- 아직 실연결을 하지 않은 로컬 화면은 참가할 수 있다고 표시하지 않는다. 리허설 페이지의 이름·인원은 예시임을 안내한다.
- 남은 P3 사용감 항목: 모집 소식이 만료된 뒤 기존 신청을 취소하려면 `우리 과 팀 찾기` → `내 신청 대기` 팀 카드로 재진입한다. 취소 API/신청 상태는 유지되지만 만료된 소식 지도에는 취소 버튼이 먼저 노출되지 않는다. 만료 타이머는 실행 회귀로 검증했으며 실제 브라우저에서 시간을 기다리는 별도 캡처는 만들지 않았다.
- stage/commit/push/배포/원격 DB 변경은 하지 않았다. 기존 루트와 격리 작업공간의 범위 밖 변경은 보존했다.
