# 활동 선택 → 자동 모집방 수정 계약 (2026-09-07)

최신 사용자 요청: 게임 활동 사진의 `모임 보기`는 같은 목록의 필터를 바꾸는 버튼이 아니라 해당 활동의 자동 모집방으로 이동해야 한다. 첫 방을 시스템이 준비하고, 5명이 차면 다음 방을 준비한다. 이번 요청은 이미 승인한 동선의 수정이며 새로운 디자인 승인 대기가 아니다.

## 완료 기준

1. 활동 ID별 주소로 이동한다. 같은 맛집 카테고리의 카페/식사 등도 별도 방 목록이다.
2. 방 개수, 방 번호, 현재 인원/정원, 모집 중/정원 마감/내 방 상태를 서버 값으로 표시한다. 선택한 참여 성별 조건을 전달하며 추천 남성/여성 레일은 참가 권한으로 사용하지 않는다.
3. 게임 정원은 5명. 기존 배드민턴·테니스 복식 4명 등 종목별 정원은 보존한다. 사용자가 방 제목·시간·장소를 먼저 작성할 필요가 없다.
4. 첫 방 및 만원 후 다음 방은 서버에서 원자적으로 마련한다. 조회 GET은 데이터를 생성하지 않는다. 중복 요청, 정원 초과, 여러 빈방 생성을 방지한다.
5. 참여 후 바로 방에서 익명 채팅하며 시간·장소를 조율한다. 기존 매칭의 지연 채팅·학과대항·직접 개설 모임을 변경하지 않는다.
6. 로그인/프로필/권한/연결 실패를 구분한다. 실패를 `0개 방` 또는 참여 성공처럼 꾸미지 않는다.
7. 기존 사진 contain과 모바일 스와이프 수정을 보존한다. 390px/데스크톱 실제 이동·뒤로가기·새로고침·버튼 상태를 확인하고 캡처한다.

## 실행과 소유권

- 부모: 새 로비/방 화면, route/API 연결, 계약 테스트, 브라우저 검증, 최종 보고.
- UI 자식: MeetupIdeaCylinder / MeetupHub의 활동 선택 링크 및 관련 회귀 테스트만.
- 서버 자식: 기존 계약 조사 후 확정된 자동방 SQL 및 embedded PostgreSQL 행동 테스트만. 실제 DB 적용 금지.
- 독립 검토자: 최종 diff·실행 증거로 인증/권한/정원/명확성을 검토한다.

## 안전 범위와 증거

- 현재 격리 작업공간의 더티 사용자 변경 보존. stage/commit/push/배포/실제 DB migration 적용은 하지 않는다.
- 기존 activity_meetups는 방장·예약시간이 필수다. 가짜 방장 또는 가짜 확정시간을 넣지 않고 모집방 모델을 분리하거나 명시적으로 지원한다.
- 타입/API/SQL은 함께 검토한다. 학교 격리, 등록 성별 조건, 차단, 계정 유효성, 멤버 전용 채팅을 유지한다.
- SQL은 임시 인메모리 PostgreSQL에서 동작 확인한다. 실제 Supabase 다중계정/다중연결 동시성 및 운영 적용 증거와 구분한다.
- 로컬 기존 DB에는 이전 통합 migration도 미적용이다. 이를 숨기지 않으며, 새로운 방 서버 적용이 필요한 경우 최종 보고에서 별도 승인이 필요한 항목으로 표시한다.
- 실제 데이터 화면과 검수용 fixture 화면은 명확히 구별한다. 운영 URL에 fixture fallback을 넣지 않는다.
- 차단 충돌로 유일 모집방에 참여할 수 없는 경우 새 우회 방을 만들지 않고 명시 거절한다. 이미 참여한 뒤 차단되어 채팅을 열 수 없더라도 오류 화면에서 본인 탈퇴는 가능해야 한다.
- 한 풀에서 한 사람은 한 방만 참여한다. 재시도는 기존 가입 결과를 돌려주며 UI는 다른 방 참가 버튼을 비활성화한다.
- 새 메시지는 최신 100개까지 서버에서 시간/ID 순서로 반환한다. 아래 사용자 교정에 따라 더 이전 대화 조회도 포함한다. 운영자 종료/보관 화면은 이번 자동 모집 동선 수정에 포함하지 않는다.

## 사용자 교정: 빈자리 재모집과 기존 약속 확인

1. 목표: 기존 방 유지. 1번 5/5 + 2번 2/5에서 한 명 탈퇴하면 1번 4/5 + 2번 2/5를 함께 모집한다. 방/참가자를 합치거나 다른 방을 닫지 않는다. 새 회원이 1번에 들어가면 5/5 + 2/5이며 불필요한 3번은 만들지 않는다.
2. 목표: 새 참가자도 이전 약속 파악. 입장 전 메시지까지 읽을 수 있으며, 약속이 최근 100개보다 오래됐어도 이전 대화 불러오기로 확인한다. 이미 불러온 기록은 최신 갱신으로 사라지지 않고 스크롤 위치를 보존한다.
3. 보안: 실제 참여 성공 전이나 탈퇴 후에는 과거 대화를 공개하지 않는다. 학교/성별/계정/차단 검사를 매 페이지에 적용한다. 단순 방 나가기는 이전 메시지를 삭제하지 않는다. 기존 계정 삭제 및 작성자 자격 필터는 이번 교정에서 약화하지 않는다.
4. 증거: 정확한 8인 SQL 행동 시험, 100개 초과 keyset·동일 시각·권한 회귀, API 및 UI 동작 확인, 예시 표시가 있는 4/5+2/5와 입장 전 약속 캡처. 실제 DB 적용은 계속 별도 승인이다.
