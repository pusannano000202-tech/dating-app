# 보이스 카테고리 정리 — 구현·검수 장부

**Goal:** 기존 승인된 사진형 보이스 화면을 목적별로 묶고, 기존 참여 흐름을 유지한다.
**Architecture:** 상위3개 카테고리 → 해당 하위주제 사진 → 기존 팀/역할/학과 모집방. UI 분류만 변경하며 DB·API·권한·정원·실제 인원 집계는 그대로 둔다.
**Tech stack:** 기존 Next/React, CSS modules, Node test runner.

## 승인·완료 기준

사용자: “LCK, KBO 축구 … 응원하기 … 연애, 취업 … 대화 … 학과끼리 … 카테고리별로 묶어가지고 … 디자인”. 현재 디자인의 명시적 분류 정정이므로 새로운 시안 승인 절차를 반복하지 않는다.

1. 응원하기: LCK/KBO/축구. 이야기 나누기: 연애/취업/수다. 우리 학과: 학과 모집방. 기존7개 주제 누락·중복 없음.
2. 카테고리를 바꾸면 그 안의 사진과 주제만 노출한다. 다른 카테고리의 팀 선택/동의/오류/공식방 패널은 남기지 않는다. 사진 넘기기도 현재 카테고리 안에서만 순환한다.
3. LCK/KBO 팀 선택, 연애/취업/수다 URL, 학과 공식방 진입, 축구 준비 중 상태와 provider 미연결 차단을 유지한다. 단일 학과 장면에는 의미 없는 넘기기 버튼을 표시하지 않는다.
4. 모바일390×844·데스크톱1440×900에서 카테고리3개를 확인하고, 선택/사진/입장 버튼을 직접 클릭한다. 사진 잘림·가로 넘침·버튼 겹침을 검사하고 캡처한다.

## 검수 결과

### 실제 구현

| 먼저 고르는 목적 | 그 안에서 넘기는 사진 | 이어지는 기존 흐름 |
| --- | --- | --- |
| 응원하기 | LCK / KBO / 축구 | LCK·KBO 팀 선택 → 방 목록. 축구는 준비 중 유지 |
| 이야기 나누기 | 연애 / 취업 / 수다 | 연애·취업은 말하기/듣기 역할 선택. 수다는 역할 구분 없는 기존 대화 준비 |
| 우리 학과 | 학과 사진 1장 | 같은 학과 공식 모집방. 자동 친구 추가 없음 |

사진은 기존 `object-fit: contain`을 유지한다. 카테고리 전환마다 해당 사진 탐색을 새로 시작하고, 이전 카테고리의 팀/동의/패널 상태를 초기화한다. 공식 모집방 주제 선택 역시 현재 카테고리 안으로 제한했다. 서버의 topic 값이나 정원·입장 규칙은 바꾸지 않았다.
