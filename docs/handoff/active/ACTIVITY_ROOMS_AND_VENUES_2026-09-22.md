# 활동별 모임방과 추천 장소 조사 — 2026-09-22

## 승인 범위와 담당

- 사용자 앱: 활동 선택 → 해당 활동의 방목록 → 방 만들기/참가 흐름을 연결한다.
- `Quantum 출시 후보 현황 점검`: 아래 실제 콘텐츠에 필요한 장소를 조사한다. 부산대 생활권 우선은 현재 콘텐츠에 따른 작업 가정이다.
- 성준(관리자/업장): 조사된 후보를 실제 제휴·예약 연결 업장으로 승인하는 관리 경계에 영향이 있다. 이 문서는 해당 기능이 완성됐다는 보고가 아니다.
- 검증한 변경만 사용자 공유 브랜치 `codex/유저-퀀텀`에 기록한다. main 병합, 배포, 운영 DB, 실제 예약·결제·업주 연락은 이번 범위 밖이다.

## 활동별 방목록 구현 계약

1. 바깥 탐색 화면은 활동을 고르는 곳이다. 소품숍 사진을 반복하며 개별 방을 나열하지 않는다.
2. 활동 화면에서 자동 번호방과 그 활동으로 직접 만든 모임을 함께 찾는다. 제목/사진 추정이 아닌 정확한 `activity_key`로 연결한다.
3. 자동 번호방의 바로 참여와 직접 만든 모임의 상세 → 보증금 확인 → 참가 신청 → 방장 수락을 구별한다. 목록 통합은 참여/결제 규칙 통합이 아니다.
4. `모임방 만들기`는 현재 활동과 성별 조건을 넘기고 모집 단계부터 시작한다. 활동 변경은 사용자가 명시적으로 선택한다.
5. 오래된 `activity_key IS NULL` 모임은 기존 분류별 모임 찾기에서 계속 접근한다. 임의로 활동을 추정하여 데이터를 바꾸지 않는다.
6. GET `/api/meetups`의 선택적 `activity_key` 필터는 서버에서 페이지 제한 전에 처리한다. 기존 필터 없는 호출과 v4는 유지하고 신규 v5 조회 함수로 분리한다. 학교·학과·성별 범위와 keyset 커서는 유지한다.
7. 전체 방 수를 일부 로드한 페이지 길이로 표시하지 않는다. 조회 실패를 방 0개로 위장하지 않는다.

## 조사 산출물과 관리 연결

콘텐츠별 공식 근거가 있는 후보 2~3곳을 목표로 하되, 근거가 없으면 수를 채우지 않는다.

`콘텐츠 key → 장소명 → 주소/집합점 → 지도 링크 → 공식 예약 링크/연락 방법 → 신청 자격 → 인원/코트·테이블 수 → 비용·기준 시간 → 운영시간 → 장비 → 취소·우천 조건 → 접근성 → 출처 URL·확인일 → 미확인 질문`

- 후보 / 공식 예약 방법 확인 / 운영자 승인·제휴 연결 상태를 구분한다.
- 실시간 빈자리나 예약 성공을 확인 없이 보장하지 않는다.
- **사용자 GPS·위치 추적·위치 권한은 제외**한다. 공개 장소 주소와 지도 링크만 필요하다.
- 조사팀은 코드·DB를 수정하거나 실제 예약/문의/결제를 하지 않는다.
- 성준 측은 향후 콘텐츠별 추천 장소 연결, 정보 확인일/공개 승인, 예약 요청을 받을 실제 업장 ID와 담당 권한을 관리해야 한다. 이번에는 요구 전달이며 구현 완료가 아니다.

## 모집 도움말 제안

소모임 공식 FAQ에서 모임 링크 친구초대와 공지·준비물 공유를 확인했다(2026-09-22): https://www.somoim.co.kr/helps . 자동 모집 보장이나 작성 코치가 있다는 뜻은 아니다.

퀀텀에는 새 긴 페이지 대신 생성 후 접힌 `사람 모으는 팁`을 제안했다. 방향 확인 전까지 확정 UI로 간주하지 않는다.

1. 누구와 무엇을 할지: 활동·난이도·처음 오는 사람도 가능한지.
2. 참가 판단 정보: 날짜·시간·공개 집합점·예산·준비물. 미정은 함께 정한다고 표시한다.
3. 실제 예약 전에는 예약 완료라고 쓰지 않는다.
4. 기존 모집 링크 공유 → 참가 신청 확인 → 수락한 사람과 첫 인사·약속 확정.

추천 장소 후보 노출, 실제 업장 예약 연결, 모집 도움말은 각각 검증·승인 상태를 따로 기록한다.
