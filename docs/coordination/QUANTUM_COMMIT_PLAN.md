## 4. 커밋 경계

커밋은 아래 순서로 나누며 `git add .`를 사용하지 않는다.

1. `governance`: `AGENTS.md`, 협업 규칙, 모델 라우팅과 작업방 운영 문서
2. `specs`: 사용자가 승인한 현재 제품 설계와 구현 계획
3. `qa`: 보안 감사, 화면 검증, 원격 상태 증거
4. `campus-eats-metadata`: 실제 대진을 재현하는 최소 메타데이터
5. `tools`: 재현 가능한 조사 및 검증 도구
6. `assets`: 실제 코드에서 참조되고 사용권이 확인된 런타임 자산
7. `archive-markers`: 대체된 문서의 상태 표시와 문서 인덱스

각 커밋은 다음 조건을 모두 만족해야 한다.

- 스테이지 파일 목록이 사전 목록과 정확히 일치한다.
- 제품 코드, DB migration, 대형 원본, QA 캡처가 한 커밋에 섞이지 않는다.
- 문서는 `CURRENT`, `SUPPORTING`, `SUPERSEDED` 중 상태가 명시된다.
- 코드 또는 자산 커밋은 관련 테스트와 실제 화면 검증을 동반한다.
- `supabase/migrations/`, 공용 타입, 인증 및 결제 경계는 별도 위험 검토를 거친다.
- push, 원격 migration, Vercel 배포, EAS 빌드는 각각 별도 승인과 증거를 남긴다.
