## 검증한 내용

- CSS viewport: **390×844**, **1440×900**, 축소 공간 **320×740**. 세로 스크롤바가 있으면 실제 콘텐츠 폭은 각각 375/1425/305px이다. 캡처 bitmap 크기를 CSS viewport와 혼동하지 않는다.
- MBTI ENFP 선택 후 INFP 2회·INTP 1회 → 경험별 현재 연애/5점/대화 선택 → 이전/다음에도 유지. 동의 체크 후 관계 상태를 바꾸면 동의가 해제됨을 DOM에서 확인했다.
- 경험 카드 1→2 전환 시 한 카드만 열리고, 모두 접기도 가능했다. 단계 전환 스크롤 위치는 처음으로 돌아온다.
- 통계로 갔다가 내부 모임 메뉴를 누르면 이탈 확인창이 표시된다. 취소 후 3회가 유지되며, 브라우저 Back에서도 경고가 표시되고 Escape 취소 후 ENFP 선택/URL이 유지됐다.
- 배달 재시도 중 이전 오류가 사라지고 로딩으로 바뀐 뒤 실제 실패 안내로 돌아왔다. 방문 맛집 대안은 정상 이동했다.
- 맛집 모바일 시작 버튼은 CSS y=720~768, 하단 메뉴 시작 y=780으로 겹치지 않았다. 선택→대결→결과를 실제 클릭했다. 해당 맛집 결과는 로컬 브라우저 취향 기록이지 전체 이용자 집계 증거가 아니다.
- 모임 스터디 필터·주제 표시, 예정표 펼침/접기, 오류 목록 재시도를 확인했다.
- 보호된 매칭으로 이동하면 설명 없는 잔류 대신 복구 페이지가 열린다. 원래 화면 재시도는 현재 DB 미연결 상태를 그대로 안내하고, 로그인/커뮤니티로 나갈 수 있었다. 보호 데이터는 열지 않았다.
- 마지막 공개 화면 검사에서 수집된 브라우저 error/warn 로그는 비어 있었다. 이 결과는 검사한 해당 시점·화면에만 해당한다.

## 남은 위험 또는 미검증 사항

1. 실제 Supabase 계정·쿠키 갱신·역할 간 저장 반영·RPC 재시도·주간 신청 배정·후속 회차 생성은 **미검증**. DB가 연결되지 않아 공개 화면 및 보호 경로의 실패 복귀까지만 브라우저로 검증했다.
2. MBTI 실제 저장/수정/철회, 공개 집계, 배달 실후보 비교는 미검증이다. 일부 성공 뒤 페이지를 강제로 떠나면 인메모리 재시도 키가 사라진다. 새 세션에서 중복 입력을 완전히 방지하려면 원격 저장 기록 확인까지 검증해야 한다.
3. 첫 저장의 확정 400/401도 보수적으로 같은 요청 재시도로 잠길 수 있다. 이 경우의 재인증/입력 수정 안내는 추가 개선 여지가 있다.
4. Navigation API 미지원 구형 브라우저의 SPA Back 경고, 실기기 제스처·스크린리더는 미검증. 현재 이탈 승인은 새 문서 이동이므로 과거 history entry를 그대로 재개하지 않는 한계가 있다. 최신 [Navigation API 명세 설명](https://github.com/WICG/navigation-api#restrictions-on-firing-canceling-and-responding)의 취소 가능 조건을 확인하고, 브라우저 이력을 강제로 재작성하지 않았다.
5. 일부 내부 응답 구조 검증은 얕아 비정상 200 응답의 모든 중첩 필드를 보장하지 못한다. 현재 내부 API 정상 계약/503 검증과 구분한다.
6. 실제 결제·환불·SMS·알림·원격 배포는 실행하지 않았다. 운영 출시 완료가 아니다.
