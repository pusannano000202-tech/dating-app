## 실제 화면 검수에서 추가 수정한 문제

1. 모임 아이디어 카드의 부모 포인터 캡처가 클릭을 가로채고, 포커스 이동이 첫 카드를 잘랐다. 카드 클릭과 스와이프를 구분하고 잘림을 수정했다.
2. 원래 G4 대진 저장 형식의 공유 세션 필드가 새 파서에서 누락될 수 있었다. 알 수 없는 기록은 원문 그대로 보호하고, 중첩 레코드까지 검증한 뒤에만 복원한다.
3. 앨범의 service-role 검사가 구형 JWT 설정만 읽어 실제 PostgREST 요청을 차단했다. 추가 migration에서 `auth.role()`을 사용하고 누락/일반 사용자 권한은 거부하도록 수정했다. 주간 배정도 동일한 명시적 검사로 감쌌다.
4. 진행 중인 회차에서 완료 후 API를 호출해 연결 장애처럼 표시되었다. 완료 상태에서만 해당 후속 선택을 조회하도록 수정했고, Day 4 종료 전후 실제 화면에서 확인했다. 비참석자·타인 회차의 404 보호는 유지한다.
5. 앨범 동시 업로드 검토에서 활성 업로드 점유 탈취와 늦은 업로드의 삭제 복구 경합을 발견해 수정했다. 독립 재검토에서 Critical/Important 지적은 닫혔다.
6. 완료 후 화면에서 이미 친구인 상대에게도 유료 친구 요청을 보여주는 문제를 발견했다. 주문 준비·결제 시작 전 차단, 동일 쌍 잠금, 과거 전달/거절과 현재 미해결 상태 구분, 외부 승인 증거 보존, 재시도 409 안내를 구현했다. 금액이나 결제 정책을 바꾸는 작업이 아니다.
7. 실제 SQL에서 만료 요청 정리가 기존 사용자 상태 변경 guard와 충돌했다. private helper의 정확한 만료 처리 동안만 사용자 claim을 비우고 성공/예외 모두 복원하도록 수정했으며, 사용자 claim 복원도 검사했다. 일반 사용자의 수락·거절 권한 제한을 풀지 않았다.
8. 내보내기 검토에서 범위가 넓은 키 검사와 학교 변경 후 남는 백업 안내를 수정했다. 정확한 현재 학교·음식 2개 키만 읽고, 다른 scope로 이동하면 원문과 안내를 지운다. 앱 내 브라우저에서 다운로드 완료를 확인하지 못해 읽기 전용 원문 대체 동선도 실제 검수했다.

1. **주간 배정의 실행 주체:** 현재 원자적 배정 API/RPC는 있지만 어떤 신청을 어떤 회차에 배정할지 선택해 호출하는 운영 UI/배치가 아직 없다. 운영자가 직접 확정할지 자동 배정 규칙을 둘지 먼저 확정해야 한다. 임의의 공개 모집이나 임의 배정은 만들지 않았다.

3. **공개할 데이터:** 실제 주간 일정·장소·정원, 검증된 배달 후보 8개 이상, 사진 사용권, 운영 feature flag와 담당 계정을 준비해야 한다. 기존 fixture를 실제 운영 증거로 바꾸지 않는다.
