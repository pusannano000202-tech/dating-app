## 1. 인수인계를 다시 받은 결과

`Quantum 출시 후보 현황 점검`(01a02ed4-9776-7ca1-ac7b-1818c7f83389)에 사용자의 요청을 전달했고, 읽기 전용 재감사 결과를 회수했다. 그 작업의 새 검증은 코드·문서·3010 HTTP 응답까지이며 실계정 여정 재실행은 아니다.

기준 작업공간은 `integrated-campus-20260905`, branch `codex/integrated-campus-20260905`, HEAD `be9078565d8e59f73cbc017f3c7b1484996da1c3`다. 시작 dirty 441건(수정95/untracked346/staged0)은 기존 통합 작업이며 이번 새 변경량이 아니다. 원본 `tonight-maps-roles-release`, `quantum-main-integration-20260819`, `quantum-five-meeting-g4-shell`, 루트는 수정하지 않는다.

### 바로잡은 이해

1. **일반 활동 모임과 연애 매칭 그룹은 다른 기능이다.** 원본 일반 모임은 성별 무관이고 학교·카테고리·시간·정원으로 참가한다. 과팅의 혼성 그룹이나 동성 친구 묶음을 일반 모임의 성별 전용 모집 기능으로 설명하면 안 된다.
2. **5일 콘텐츠는 별도 앱/별도 연애 프로그램이 아니다.** 오늘/주간 첫 만남의 같은 사람들이 동의하여 이어가는 콘텐츠다. 첫 보드게임→다음 Day2, 다른 활동→다음 Day1 보드게임. 실제 만남 번호와 콘텐츠 Day를 구분한다.
3. **저장 골격 구현과 이전 콘텐츠 전체 보존은 다르다.** 통합판에는 상태/API/DB가 있지만 FIVE의 장면 안내와 일부 상호작용이 축약됐다. ‘Day1~5 구현’이라는 이전 보고를 원본 전체 이식 완료로 해석한 것이 부족했다.

출시 후보 작업이 지적한 총5/6회 미결정은 최신 전체 승인 장부로 정정 회신했다. `2026-09-05-integrated-campus-experience.md` C-ENTRY와 실행 장부의 `3번으로 하고 전체 구현 시작해라` 승인에 따라 콘텐츠5일을 보존하며 실제5/6회를 유지한다. 다시 5회로 줄이거나 Day5를 삭제하지 않는다.

## 4. 이번 변경과 검증

- 매칭의 오늘/이번 주 입구를 유지하면서 ‘이어 만나는 5일 코스 알아보기’를 연결한다. 실제 신청/확정 일정이 아닌 설명 영역이다.
- 기존 회차 화면에도 같은 장면 안내를 연결한다. 권위 진행은 기존 API 응답으로만 판단한다.
- 원본 장면·구성 변형 그림37개를 명시 허용 목록으로 복사했다. 기존 파일을 덮어쓰지 않았고 각 원본/대상 SHA256이 일치했다.
- 달무티 원본14컷도 허용 목록으로 이식·해시 일치를 확인했다. 14번째는 강요 규칙이 아닌 안전한 `scene-14-v2`와 상호 존중 문구다.
- 5명일 때 한 쌍+세 명 조, 6명일 때 세 쌍을 안내하는 원본5개를 추가해 총 **51개 원본 이미지**를 이식했다. 실제 조 배정이 구현됐다고 주장하지 않는다.
- 시간표는 Day1 150분, Day2 120분, Day3 180분, Day4 120분(30~50분에10카드), Day5 120분을 원본 장면별 구간과 함께 복구했다. 실제 경과 시간이나 서버 완료 상태가 아닌 예시 순서로 표시한다.
- 실제 회차에서는 안내를 기본 접힘으로 분리했고, Day2 다음 질문 버튼도 선택형 질문 패널 안으로 옮겼다. 현재 회차 전체가 한 질문을 공유한다는 한계를 표시했다.
- 홈 신청과 후속 조회 실패 상태를 분리했다. 후속 실패로 성공한 신청을 지우지 않고, 기존 신청도 없고 후속이 불명일 때는 새 신청 추천을 열지 않는다. 잘못된 참여 응답도 정상 부재로 처리하지 않는다.

### 교차 점검으로 추가 발견한 보존 문제

- 홈: 기존 참여·통계·후속 조회를 한 묶음으로 실패 처리해 후속 API 장애가 정상 참여까지 가렸다. 기존 신청을 유지하고 후속 오류만 분리하도록 수정했다.
- 주간: 옛 `QuantumEventWheel` 비연결 자체는 결함으로 단정하지 않는다. 최신 승인 계획은 활동 탐색→복수 가능 날짜→한 신청→한 배정이다. 다만 구 초대·수락·2~3명 동성 친구·동반 그룹 식별자가 새 weekly DTO/RPC에 없고 배정이 `solo/group=null`로 고정된다. **친구 동반 보존은 미완료**다.
- 주간 배정 시 일정 겹침은 서버가 막지만 후보 선택 단계의 사전 충돌 경고는 실제 UI에 연결되지 않았다.
- 커뮤니티 활성/맛집 비활성인 운영 플래그 조합에서는 방문·배달 CTA가 404로 향할 수 있다. 로컬 개발에서는 둘 다 열려 이 문제가 감춰진다. 운영 flag를 임의로 켜지 않으며 아직 미수정이다.
- 만남 완료의 예전 친구 프로필 버튼은 후속 진입으로 바뀌었다. 자동 친구 복원은 금지하고, 실제 참석자 자격 확인 후 명시 요청·수락 기능을 보존해야 한다.

### 다음 구현 계약에서 놓치지 않을 항목

주간 친구 동반은 버튼만 복원할 수 없다. 친구 수락, 모두 가능한 날짜, 모든 구성원의 준비·정원·일정 충돌, 같은 팀 보장, 한 명 취소 시 처리까지 저장/API/배정에서 함께 보장해야 한다. 일반 모임의 성별 분류/참가 제한과는 다른 계약이다.
