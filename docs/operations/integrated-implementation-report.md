# 3번 디자인 · 전체 통합 구현 보고

## 판정

간편 가입, 다중 경험 MBTI, 오늘/이번 주 모집, 후속 5회 만남, 모임 목록, 방문·배달 월드컵을 같은 격리 작업공간에 구현했다. 전체 범위를 일부 기능만의 출시로 축소하지 않았다. **운영 출시 및 전체 실제 사용 검증 완료는 아니다.** 실제 DB, 배달 자료, 실계정·실기기·운영 환경 증거가 남아 있다.

## 검증한 내용

- 최종 자동 회귀 **1,643/1,643 통과**: auth 144, config 608, matching 752, profile 139. 마지막 실행은 2026-09-06 01:50:46–01:51:32 KST이며 모든 시험 exit code 0이다. 근거는 `artifacts/integrated-20260905/checks/test-results.json`과 개별 로그다. 소스 계약 시험을 포함하므로 실제 DB 실행 통과 수가 아니다.
- 별도 도구 회귀는 migration 검사기 20개와 격리 DB/앱 구성 3개가 통과했다. 정식 빌드(179개 페이지), lint, secrets, migration baseline 검사가 모두 exit code 0으로 통과했다. 원문은 같은 폴더 `final-results.json`과 로그에 있다.
- 신규 SQL 9개와 모든 PL/pgSQL을 PostgreSQL 17 문법으로 검사했다. **실제 DB 적용이 아니다.** 전체 migration 정적 검사는 기존 baseline 232개를 늘리지 않고 신규 경고 0개로 통과했다. 현재 남은 24개 경고도 실제 DB 검증을 대신하지 않는다.
- 브라우저: MBTI 반복 입력·개별 평가·동의 미선택 저장 비활성·통계 건너뛰기, 모임 필터/새로고침 복원/사진 넘기기, 방문 월드컵 우승/개인 결과 재조회, 배달 미확인 차단, 전화번호 서비스 미설정 차단을 클릭했다.
- 모바일·데스크톱 캡처 및 원본 대비 검토는 루트 `design-qa.md`에 있다. 실제 DB 사용자·업장·운영자·최고관리자 검증과 섞지 않았다.

## 발견한 문제와 수정 내용

- 통계: 최소 가입 우회, 과도한 단일 횟수 입력, 비원자적 집계, 미래 출석 반영, 오래된 멱등 키로 다른 요청을 성공 처리하는 결함을 수정했다. 독립 검토가 소스 수준에서 재확인했다.
- 후속 만남: 마감 후 결제/일정 정지, 출석 정정 후 하위 상태·친구 권리 잔존, 주간 명단 원장 감시 누락, 신규 후보 동의 화면 404, 4+1 합류 최소 인원 계산을 수정했다.
- 결제 재시도: 유효한 기존 주문은 재사용하고, 만료 주문은 복구 상태로 정상 저장한 뒤 새 요청과 분리한다. 준비 중/확인 중 주문 모두 만료를 검사하며, callback 응답 상태를 판정한 뒤에만 Toss 확인을 호출하도록 고쳤다. 후속 만남 독립 감사 지적 #1–#7은 현재 소스 기준 PASS, 독립 source-contract 시험은 20/20 통과다. 실제 Toss/DB 성공으로 해석하지 않는다.
- 배달: 공개 RPC로 사진 파일 검사를 우회할 수 있던 경로를 서버 전용으로 제한했다. 관리자 목록에 사진 파일 미확인을 표시하고, 입력 변경/저장 후 검수 체크를 해제한다.
- 전화번호: 신뢰하지 않은 전달 IP 헤더를 바꿔 발송 제한을 회피하지 못하게 했다. 검토되지 않은 운영 ingress에서는 발송을 막는다.
- 도구: SQL 검사기의 CTE/테이블 함수/EXTRACT/트리거 이벤트 오인식을 회귀 테스트로 보강했다. 초기 manifest의 도구 출력 잘림은 원본 보관 후 현재 파일 해시 목록으로 복구했다.

## 남은 위험 또는 미검증 사항

- **Docker/DB:** Engine이 시작되지 않아 실제 migration·RLS·복수 계정 경쟁·재시작 저장 유지·4역할 전체 여정은 미검증. factory reset·볼륨/DB 삭제·WSL 강제 종료를 하지 않았다.
- **배달 자료:** 실제 검수 후보는 0개이며 8개 기준 미달. 사진 권리·같은 공용 권역·메뉴 하나 주문 조건이 확인된 자료가 필요하다. 빈 화면을 전체 기능 완료로 계산하지 않는다.
- **후속 재검토 상태:** 출석/명단 정정 시 `review_required`로 잠가 새 진행을 막는다. 과거 동의·결제를 자동 복원하지 않는다. 운영자 재승인·재동의 복구와 정책은 실제 운영 검수에서 확인해야 한다.
- **운영:** SMS 계약, Toss 실계정 샌드박스/실결제/실환불, Push 실기기, 원격 DB, cron 설치, Vercel/EAS 배포는 미검증·미적용.
- **사용성:** 실제 대상자 5명 중 4명 무도움 완료와 10초 이해 기준은 관찰하지 않았다.
- **Git:** 새 격리 branch `codex/integrated-campus-20260905`, 기준 HEAD `be9078565d8e59f73cbc017f3c7b1484996da1c3`. stage/commit/push 없음. 더티 파일에는 보존한 G1 baseline도 포함되므로 전체 변경 파일 수를 이번 새 구현량으로 말하지 않는다.

다음 실행은 `integrated-local-run.md`의 전용 DB 절차를 사용한다. 원본 작업공간을 초기화하거나 운영 환경을 대신 변경하지 않는다.
