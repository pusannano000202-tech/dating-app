# 매칭: 승인된 단계형 화면 구현

## 기준과 범위

- 기준 작업공간: `web-security-main-20260914`, 시작 HEAD `32563ad3`.
- 2026-09-15 사용자 승인: 기존 모임의 사진 카드/아이보리/테라코타 디자인 유지. 한 화면에 현재 단계만 표시하고 세로 적층을 피한다.
- 승인 시안: `exec-dd6b5909-c23c-4520-ba7c-9d258ed1bdaf.png`. 오늘밤 사진의 부산대/부산 간판은 제거한 별도 사진으로 교체한다.
- 입구: 오늘밤 만나기 / 이벤트 캘린더. 연애 중에는 싱글 오늘밤 신청 대신 날짜가 정해진 커플 이벤트로 안내한다. 연애 상태 관리는 마이에 유지한다.
- 이벤트: 운영자가 제공한 실제 날짜·활동·장소만 표시. 날짜 선택 → 행사 상세 → 참가 확인 → 신청 상태로 나눈다. 신청 전 자동 등록 금지.
- 커플: 내 연인과 함께 다른 커플을 만나는 2커플/4명 행사. 파트너 직접 수락과 각자 10,000원 보증금 검증이 필요하다. 기존 5인 싱글 원장에 억지로 편입하지 않는다.
- 집계: 오늘 회차 남녀 신청 인원, 실제 팀 수, 행사별 신청 인원. 다른 회차/학교/취소된 신청을 섞지 않으며 조회 실패를 0명으로 표현하지 않는다. 주기 갱신과 탭 복귀 갱신, 조회 시각을 제공한다.
- 안내: 자기소개 등 참가자의 다음 행동을 한 카드씩 안내. 미리보기와 실제 진행 상태를 구별하고 기존 만남·채팅·출석·동의 규칙을 유지한다.
- 5회 만남은 기존 첫 만남 이후 이어가는 흐름이며 오후 만남/세 번째 모집 입구가 아니다.

## 보존 / 권한 경계

홈·모임·커뮤니티·기존 채팅 및 기존 매칭 상태/취소/초대 동선을 제거하지 않는다. 루트 더티 변경과 기존 next-env.d.ts/tsconfig.json 변경은 보존한다. 새로운 기능에 필요한 로컬 코드/테스트/전진 migration만 작성하며 stage/commit/main 병합/push/원격 migration/실결제/배포는 이번 구현으로 수행하지 않는다.

안전한 결제 원장 연결이 없는 신규 행사에는 결제 완료/신청 완료를 임의로 만들지 않는다. 날짜 고정, 참여자 소유권, 금액·원거래·환불 경로의 검증이 선행돼야 한다. 운영 DB에 없는 행사를 실서비스 행사처럼 만들지 않는다.

1. 주 담당: 매칭 입구, 이벤트 캘린더/세부 단계, 관계 상태 표시 연결, 공유 스타일, 통합 및 브라우저 검증.
2. Tonight 담당: 오늘밤 단계 UI, 기존 다음 행동 보존, 공용 코칭 카드 및 순수 로직 테스트.
3. 데이터 담당: 달력 API/날짜 바인딩/커플 신청 계약, 집계 및 현재 회차 팀 수, 관련 전진 SQL와 테스트. 새 금전 원장 범위는 주 담당과 명시 조정한다.
4. 이미지 담당: 승인 사진의 독립 이미지 자산 생성/간판 수정/최적화. 기존 이미지는 삭제하지 않는다.
