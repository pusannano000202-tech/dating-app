# Quantum 대표실 보고

이 스킬은 사용자가 각 작업방을 직접 따라가지 않아도 대표실 보고만으로 결정하게 하는 장치다. 다음 경우에만 사용한다.

- 별도 작업방을 열어 사용자에게 보일 조사·디자인·구현·출시 결과를 만든다.
- 사용자 승인 Gate를 확인하거나 다음 Gate를 열어야 한다.
- 여러 작업방 결과를 대표실로 회수해 하나의 사용자용 보고로 통합한다.

읽기 전용 사실 확인, 잠긴 단순 수정, 부모가 관리하는 내부 하위 에이전트에는 이 스킬을 적용하지 않는다. 그 경우 `quantum-model-router`의 짧은 ownership·금지·합격 기준만 사용한다.

## 승인 경계

| Gate | 승인 전 허용 | 승인 전 금지 |
|---|---|---|
| G0 문제·목표 | 현황 확인 | 해결안 확정 |
| G1 조사·후보 | 읽기 전용 조사 | 디자인·구현 확정 |
| G2 디자인 | 시안·프로토타입 | 앱 코드, DB/API, 구현팀 착수 |
| G3 규칙·기술 설계 | 문서형 설계·검토 | 실제 기능 구현 |
| G4 구현 | 승인 범위 코드·검증 | `git add`·commit·push, 원격 DB/Auth/Storage/RLS/RPC·migration 적용, 실제 결제, production 배포·제출 |
| G5 출시 | 출시 판단 자료 | 사용자 승인 없는 배포 |

정확한 사용자 승인 문장 또는 승인 산출물 경로가 없으면 다음 Gate를 열지 않는다. 추천·완료 보고·질문·긍정 반응은 승인 근거가 아니다. 코드·문서 수정 승인도 Git 기록, 원격 DB, 결제, 배포 승인을 대신하지 않으며 각 범위를 별도로 확인한다.

## 대표실 운영

1. 현재 Gate, 승인 근거, 아직 열리지 않은 범위를 확인한다.
2. full lane이면 `quantum-model-router`의 resolved routing을 만든다. 같은 트리의 내부 자식에는 그 계약을 전달하고 이 스킬을 재적용하지 않는다.
3. 현재 Gate에서 필요한 별도 작업방만 연다. 디자인 미승인 상태에서 구현·Supabase·결제·팀장 작업방을 열지 않는다.
4. 결과를 회수해 증거·금지 범위·미확인을 확인한 뒤, 사용자에게 하나의 통합 보고로 보여준다.
5. 다음 사용자 승인을 기다린다. 작업방은 다른 방을 직접 열거나 사용자에게 직접 승인받지 않는다.

## 별도 작업방 지시

```text
작업 ID / 작업방:
현재 Gate와 승인 근거:
이번 목적과 허용 범위:
금지 범위:
resolved routing (모델·강도·파일·합격 기준·승격 조건):
중단 조건:
대표실 반환 대상과 필요한 증거:
```

작업방은 완료·차단 모두 대표실에 반환하고, `확인됨 / 추정 / 미확인`을 구분한다. 다른 작업방에 직접 지시하지 않고 후속 후보만 제시한다.

## 사용자용 통합 보고

1. 현재 상태 한 문장
2. 실제로 볼 결과(디자인이면 대표 이미지 2~4장; 없으면 `이미지 없음`)
3. 쉬운 설명 최대 3개
4. 추천안과 이유, 다른 선택지
5. 사용자 결정 최대 3개
6. 승인 후 열릴 작업방
7. 코드·문서·Git·production 변경과 남은 위험

증거가 없으면 `미확인`으로 적고, 사진 권리·워터마크·모바일 잘림·클릭이 미확인이면 디자인 확정으로 표현하지 않는다.

## 제출 전 검사

- 이 일이 실제로 별도 작업방·승인 Gate·대표실 회수인가? 아니라면 이 스킬을 제거했는가?
- Gate와 정확한 승인 근거가 있는가?
- 승인되지 않은 다음 Gate 또는 production 작업을 열지 않았는가?
- 사용자에게 필요한 결정이 3개 이하이고, 추천과 확정을 구분했는가?
- 코드·문서·Git·production 상태와 미확인을 정확히 표시했는가?
